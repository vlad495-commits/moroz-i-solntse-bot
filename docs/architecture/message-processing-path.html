5 · доставка ответа — второй проход через RabbitMQ

Генерация ответа и отправка в Telegram разделены. Если worker упадёт между ними, готовый outbound останется в PostgreSQL и будет доставлен позднее.

durable delivery task

task_outbox: send_outbound

Payload содержит outbound_id; OutboxRelay снова публикует task в RabbitMQ.

worker router

MessageTaskHandler → TelegramSender

Task kind = send_outbound; worker не генерирует текст повторно.

ordered claim

Claim outbound по порядку чата

Advisory lock + проверка более ранних pending/sending. Состояние меняется pending → sending.

Telegram Bot API: send_message

Отправляется сохранённый text и разрешённые delivery_options.

Сохраняется Telegram message_id. При сетевой неопределённости — delivery_unknown; при определённой ошибке claim освобождается для retry.

6 · failure path RabbitMQ — применяется к любой task

ACK означает не «мы получили байты», а «задача успешно завершена либо подтверждённо перенесена в следующий retry/DLQ маршрут».

Handler выбросил exception → controlled retry

Worker читает x-retry-count, ждёт нужную задержку и confirmed-publish копию обратно в tasks exchange. Только после успешной перепубликации делает manual ACK исходного сообщения.

retry 1 · ожидание 1 секунда · x-retry-count = 1
retry 2 · ожидание 5 секунд · x-retry-count = 2
retry 3 · ожидание 30 секунд · x-retry-count = 3

Фактическая последовательность: 1 → 5 → 30 секунд.

После трёх retry → dead letter

Task confirmed-publish в tasks.dlx с routing key tasks.dlq, затем хранится в durable tasks.dlq. TTL 30 дней.

Если перепубликация retry/DLQ сама не подтверждена, исходное сообщение получает reject с requeue=true — задача не теряется.

Главная гарантия для технического владельца. Дедупликация здесь многоуровневая: Telegram update уникален в message_inbox; task уникальна в task_outbox; готовый ответ уникален в outbound_messages; а worker перед LLM ещё раз проверяет status inbox под блокировкой. Поэтому модель доставки RabbitMQ может быть at-least-once, но повторная task не должна превращаться в повторный LLM-вызов и второй ответ клиенту.

# B1: убрать устаревшие дубли Router

Область одобрена владельцем 2026-09-06: продолжить оставшиеся задачи без промежуточных согласований. Реализация только локально, не rollout.

## Решение

В Router уже публично используются services и PUBLIC_ACTIONS. Удаляем внутренний дубль RouteDecision.service, __post_init__ и приём legacy service из JSON. В ROUTE_ACTIONS удаляем непубличные price/duration/staff/clarify_cancel: консультационные темы передаются через topics при action=none. Устаревшее указание consultation/price в prompt заменяется действующим контрактом none + topics. Остальные поля, публичная JSON schema и immutable datasets/migrations сохраняются.

Простой вариант — единый services во всех потребителях, вместо бессрочной синхронизации двух полей. Защита cancel_draft проверяет весь services, а не только одиночный alias; дата по-прежнему несовместима с отменой черновика. Проверки choice и допустимых route/action сохраняются. Дубликат не является пользовательским сценарием, его удаление не должно отнимать консультации или запись.

## Приёмка

- JSON с legacy service и непубличными actions отклоняется штатным invalid-output/fallback; services и все публичные действия сохраняют прежнюю семантику.
- cancel_draft с одной или несколькими услугами либо датой не закрывает draft.
- Актуализировать только исполняемые тестовые callers; immutable dataset/migrations не переписывать.
- Docker unit Router/security/admin Evaluation и затронутые E2E зелёные; независимое review; отдельный локальный коммит.

Не заменять topics булевым признаком и не добавлять новый классификатор. Live-качество старых исторических datasets не выдавать за проверку нового контракта.

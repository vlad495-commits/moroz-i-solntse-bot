# Московское время в сообщениях о записи

## Решение

Все даты записи, которые видит клиент в Telegram, приводятся к `Europe/Moscow` и показываются в одном формате: `10.09.2026 в 12:00`. Технический ISO-формат и смещения `+00:00`/`+03:00` клиенту не выводятся.

Единый небольшой formatter используется для подтверждения создания, переноса, отмены и плановых напоминаний. Значения в БД, idempotency keys и API-контракте YCLIENTS остаются timezone-aware и не меняются.

При переносе бот отправляет одно итоговое сообщение: `Запись перенесена с <старое время> на <новое время>.` Повторное немедленное уведомление `booking_created` для перенесённой записи не планируется; будущие напоминания для нового времени сохраняются.

## Проверка

- UTC-время корректно отображается по Москве.
- Создание, перенос, отмена и напоминания используют единый формат.
- Перенос не создаёт второе немедленное подтверждение.
- Существующие будущие напоминания после переноса перепланируются на новое время.

Новые зависимости, миграции и изменения YCLIENTS API не нужны.

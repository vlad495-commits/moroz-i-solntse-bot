# Первый запуск и постоянная навигация Telegram-бота

## Контекст

Сейчас новый пользователь получает приветствие с предложением написать вопрос, а privacy gate появляется только после следующего сообщения. После подтверждения согласия бот отвечает общей фразой и заставляет пользователя повторить запрос. В сценарии записи выбор walk-in услуги закрывает сценарий, поэтому соседние видимые кнопки того же списка отвечают, что они уже неактуальны.

## Выбранный пользовательский поток

1. Новый пользователь отправляет `/start`.
2. Если действующего processing consent нет, бот сразу показывает форму согласия. Приветствие и постоянное меню до согласия не показываются.
3. Processing consent обязателен, marketing consent остаётся отдельным и необязательным.
4. После успешного `Готово` бот отправляет обычное приветствие и показывает постоянное меню.
5. Пользователь с уже действующим processing consent получает приветствие и меню сразу по `/start`.
6. Текст, отправленный до processing consent, не сохраняется и не передаётся в LLM. Бот повторяет форму согласия. Это сохраняет действующий privacy-контракт проекта; автоматическое воспроизведение раннего вопроса исключено, потому что для него пришлось бы хранить содержание до согласия.

## Постоянное меню

После согласия используется компактная persistent reply-клавиатура 2×2:

```text
📅 Записаться          ✨ Услуги и цены
📍 Адрес и режим       👩‍💼 Позвать администратора
```

- `📅 Записаться` открывает свежий сценарий выбора услуги; текстовые фразы о записи продолжают работать.
- `✨ Услуги и цены` проходит через существующий консультационный маршрут.
- `📍 Адрес и режим` проходит через существующий консультационный маршрут.
- `👩‍💼 Позвать администратора` проходит через существующий детерминированный escalation route.
- Кнопки `Задать вопрос`, `Главное меню`, `Акции` и `Мои записи` в постоянное меню не добавляются. Поле ввода уже покрывает вопросы, меню само является главным, реклама требует отдельного согласия, а управление записями остаётся доступно текстом и командой до отдельного продуктового решения.
- Временная клавиатура отправки контакта может заменить постоянное меню внутри записи. После завершения или отмены сценария постоянное меню восстанавливается.

## Выбор услуг и устаревшие кнопки

- Выбор солярия, коллариума или коллагенария не закрывает сценарий выбора услуги.
- Ответ объясняет, что предварительная запись не нужна, и снова показывает актуальный список. Кнопки исходного списка также остаются пригодны, пока пользователь находится на шаге выбора услуги.
- Повторное нажатие другой walk-in или обычной услуги обрабатывается без команды `Записаться` и без сообщения об ошибке.
- Если callback действительно устарел, отсутствует или относится к уже пройденному шагу, бот не требует начинать заново. Для текущего владельца он показывает актуальный шаг, а при отсутствии активного сценария открывает новый список услуг.
- Чужой callback не раскрывает данные чужого сценария: пользователь получает только собственный свежий список.

## Глобальная навигация

- Нажатие постоянного `📅 Записаться` во время незавершённого сценария безопасно завершает только этот незавершённый flow и открывает новый список услуг.
- Нажатие другой постоянной кнопки завершает незавершённый flow без mutation и передаёт выбранное действие в обычный router.
- Уже подтверждённые записи не меняются и не отменяются навигацией.

## Технические границы

- Используются существующие aiogram reply/inline keyboards, webhook, durable inbox/outbox, coordinator и PostgreSQL-state.
- Новые зависимости, таблицы, миграции, Mini App и LLM tool calling не добавляются.
- Callback ownership, processing consent, deletion fence, idempotency и явное подтверждение YCLIENTS mutation сохраняются.
- Production не затрагивается; после Docker-gate изменение проверяется и разворачивается только на staging.

## Проверка

- E2E privacy tests: первый `/start` без согласия, `/start` с согласием, успешный `Готово`, отсутствие сохранения раннего текста.
- Booking tests: последовательный выбор двух услуг после walk-in, восстановление свежего списка после stale callback, глобальный restart через `📅 Записаться`.
- Delivery tests: Telegram принимает persistent reply keyboard и временную contact keyboard.
- Targeted Docker regression, затем полный Docker suite и ручной staging QA через Telegram Web.

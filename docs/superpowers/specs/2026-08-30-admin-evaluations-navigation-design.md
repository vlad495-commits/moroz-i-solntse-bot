# Навигация Evaluations — дизайн

## Цель

Собрать все существующие наборы evaluation в единую страницу «Evaluations / Эвалы» с внутренними горизонтальными подкладками, сохранив данные, API, маршруты и запуск раннеров.

## Границы

- Из боковой навигации убрать отдельные ссылки Router Evaluation, Input Security, Validator Evaluation и Compact Evaluation; оставить единственную ссылку Evaluations.
- В шаблоне списка evaluation показать внутренние подкладки: Основная LLM (`answer`), Валидатор (`validator`), Роутер (`router_v2`), Input Security (`security`) и Сжатие контекста (`compact`).
- Подкладку «Стирание ПД» не создавать: в текущем приложении нет существующего suite и маршрута этого набора.
- Сохранить рабочими legacy URLs `/eval/`, `/eval/router/`, `/eval/security/`, `/eval/validator/` и `/eval/compact/`. Каждый из них отображает ту же общую страницу с соответствующей активной подкладкой.
- Не менять модели БД, датасеты, существующие POST-маршруты, audit-логи, права доступа и код eval runner.

## Интерфейс

Общий шаблон `eval_list.html` получает метаданные текущего suite и перечень доступных подкладок. Подкладки — обычные ссылки, без JavaScript-состояния: активная имеет синюю нижнюю линию, как в референсе. Так сохраняются перезагрузка, закладки и старые ссылки.

Верхняя часть каждой страницы показывает русское название набора и количество кейсов, кнопку запуска и кнопку создания нового кейса. У Основной LLM остаётся существующий параметр запуска с валидатором. Текущий список запусков остаётся источником таблицы «Последние прогоны» и показывает ID, дату запуска, статус, прошло/всего, pass rate и технические поля, уже применимые к строке (judge model и использование валидатора).

## Совместимость и ошибки

Маршруты набора остаются единственным источником `suite`, поэтому формы запуска и редактирования используют существующую логику. Неизвестный URL не создаёт нового набора и обрабатывается текущими правилами маршрутизации. Owner-only ограничения специализированных наборов сохраняются.

## Проверка

Добавить целевые admin unit/E2E-проверки: боковая навигация содержит одну ссылку Evaluations, каждый существующий legacy URL рендерит одну из подкладок активной, таблица истории и контекстные действия присутствуют, а основная LLM сохраняет опцию валидатора. Проверки запускаются только в Docker через тестовый Compose-профиль.

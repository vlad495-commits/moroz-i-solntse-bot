# Исправление позднего рекламного согласия на старой карточке

Дата: 2026-09-02  
Статус: согласовано владельцем

## Контекст

Первый consent-экран содержит два чекбокса: обязательную политику обработки данных и необязательную рекламную рассылку. Чистый сценарий, в котором пользователь отмечает оба пункта до первого «Готово», работает корректно.

Дефект возникает, когда пользователь сначала сохраняет только политику, а позднее возвращается к той же карточке и включает рекламу. После первого «Готово» временное состояние чекбоксов удаляется. Поздний клик создаёт новое состояние только `ads`, визуально снимает уже подтверждённую политику, а повторное «Готово» молча выходит при обнаружении существующего processing consent. Marketing event, proof и active consent не создаются.

## Выбранное поведение

Старая consent-карточка остаётся рабочим редактором согласий.

- Сохранённый processing consent является постоянным состоянием: карточка показывает политику отмеченной и не позволяет отозвать её этим интерфейсом.
- Текущее активное marketing consent используется как исходное состояние рекламного чекбокса.
- Пользователь может включить или выключить рекламу, затем нажать «Готово».
- Позднее включение создаёт явное `telegram_explicit` marketing event, связанный proof/hash и active marketing consent.
- Позднее выключение создаёт явный revoke/suppression через существующий consent service.
- После «Готово» временное Redis-состояние удаляется.
- Пользователь всегда получает понятный результат: первоначальное `CONSENT_THANKS`, либо `MARKETING_ENABLED_REPLY`, либо `MARKETING_DISABLED_REPLY`.

Команда `/marketing` сохраняется как отдельный прямой способ управления рекламой.

## Поток данных

1. При первом нажатии чекбокса обработчик читает Redis-state. Если state отсутствует, он инициализируется из постоянных processing/marketing consent.
2. Уже сохранённая политика принудительно остаётся в наборе `checked`; повторный клик не изображает её отзыв.
3. Рекламный чекбокс меняет только предполагаемое marketing-состояние в Redis.
4. «Готово» под существующей customer advisory lock повторно сверяет постоянное состояние.
5. Если processing consent отсутствует, сохраняется текущий обязательный first-run flow.
6. Если желаемое marketing-состояние отличается от постоянного, используется существующий grant/revoke путь. Grant получает proof из видимого `MARKETING_CONSENT_CLAUSE`, текущего Telegram update id и server receipt time.
7. Если желаемое состояние уже совпадает с постоянным, новое consent event не создаётся, но пользователь получает текущий понятный статус.
8. В одной успешной ветке очищается Redis-state и ставится в outbox один понятный ответ.

## Безопасность и идемпотентность

- Без явного checked ads marketing consent не создаётся.
- Processing consent не преобразуется в marketing consent автоматически.
- Redis-loader различает отсутствующий state и намеренно сохранённый пустой набор, поэтому постоянное marketing-состояние используется только для инициализации новой сессии редактирования.
- Все ответы одного `consent:done` сохраняют существующий idempotency key `telegram:consent_thanks:{update_id}`. Повторная доставка одного Telegram update не создаёт второй event или второй outbox, даже если после первой обработки постоянное состояние уже изменилось.
- Customer deletion guard и advisory lock сохраняются.
- Reactivation mode, eligibility, scheduler и доставка рекламных сообщений не меняются.
- Дефект остаётся fail-closed до выкладки исправления.

## Проверка

Сначала добавляется один RED E2E-сценарий, повторяющий ручное воспроизведение:

1. отметить только policy и нажать «Готово»;
2. убедиться, что processing consent есть, marketing consent отсутствует;
3. на старой карточке включить ads и снова нажать «Готово»;
4. ожидать сохранённые processing + proven marketing consent, очищенный Redis-state и ответ `MARKETING_ENABLED_REPLY`;
5. повторить тот же update и подтвердить отсутствие дублей.

Дополнительно существующие privacy/consent E2E должны остаться зелёными. После staging rollout человек повторяет тот же сценарий на controlled аккаунте и подтверждает видимые галочки и ответ.

# Telegram Walk-in Services — Design

Дата: 2026-09-04
Статус: одобрено владельцем проекта

## Решение

Солярий, коллариум и коллагенарий остаются в общем Telegram-разделе
`Записаться`, но показываются как три понятные позиции вместо десятков
технических минутных услуг YCLIENTS.

После выбора одной из этих трёх позиций бот не запрашивает специалиста,
дату, время, телефон или подтверждение и не выполняет mutation YCLIENTS.
Он сообщает, что предварительная запись не нужна, центр работает ежедневно
с 10:00 до 21:00, и позволяет вернуться к списку других услуг.

Обычные услуги продолжают существующий полный сценарий
`услуга → специалист → дата → время → контакт → подтверждение`.
Одновременно у клиента остаётся один незавершённый сценарий, но после его
завершения клиент может создать любое количество отдельных будущих записей.

## Реальные данные YCLIENTS

Customer-owned GET-only проверка подтвердила десятки отдельных минутных
позиций трёх walk-in семейств. Их `seance_length` является техническим
интервалом и не всегда совпадает с количеством минут в названии; у позиции
`Солярий | 1 минута` он равен нулю.

Для этих трёх семейств отображаемая длительность извлекается из названия
услуги. Остальные услуги сохраняют строгую проверку положительного
`seance_length`, кратного минуте. Неизвестная нулевая длительность вне трёх
подтверждённых семейств по-прежнему отклоняет весь снимок.

## Минимальная реализация

- Один общий чистый классификатор распознаёт только три подтверждённых
  русских семейства по нормализованному началу названия.
- Catalog reader принимает нулевой `seance_length` только для walk-in услуги
  с однозначным количеством минут в названии и сохраняет это количество как
  `duration_minutes`.
- Telegram coordinator сворачивает минутные позиции в три family-кнопки.
- Выбор family-кнопки закрывает текущий черновик без создания локальной
  записи и без вызова booking adapter; ответ предлагает снова открыть
  `Записаться` для другой услуги.
- Цены и минутные позиции остаются в локальном YCLIENTS-каталоге; отдельная
  таблица, миграция, dependency и настройки YCLIENTS не добавляются.

## Безопасность и ошибки

- Никакой эвристики «любая нулевая длительность = без записи» нет.
- Нельзя передать synthetic walk-in choice в `list_slots`, create, reschedule
  или cancel.
- Устаревшие и подменённые callback продолжают завершаться fail-closed.
- Provider IDs, raw response и клиентские данные не попадают в ответы и логи.

## Проверка

- contract test: `Солярий | 1 минута` с `seance_length=0` принимается как одна
  минута;
- contract test: неизвестная услуга с нулевой длительностью отклоняется;
- unit test: десятки минутных вариантов превращаются в три family-кнопки;
- unit test: выбор walk-in завершает черновик и делает ноль booking-вызовов;
- regression: обычная услуга проходит прежний flow без изменений;
- Docker targeted gate, полный релевантный regression и GET-only staging
  catalog/projection check до разрешения любых YCLIENTS mutations.

## Вне scope

- бронирование времени для walk-in услуг;
- одна составная запись из нескольких услуг;
- изменение услуг, длительности или расписания в кабинете YCLIENTS;
- новая админ-настройка семейств для нескольких филиалов.

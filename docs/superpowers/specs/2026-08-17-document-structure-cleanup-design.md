# Упорядочивание проектной документации — дизайн

## Цель

Очистить корень проекта от рабочих документов ручного QA и сгруппировать материалы `docs/` по назначению, не меняя runtime-код, staging или production.

## Целевая структура

```text
moroz-i-solntse-bot/
├── moroz-i-solntse-full-architecture.html  # удобная копия для быстрого открытия
├── План ручного тестирования.md             # переносится
├── Ручное тестирование человеком*.md         # переносятся
└── docs/
    ├── architecture/
    │   ├── message-processing-path.html
    │   ├── moroz-i-solntse-full-architecture.html  # каноническая копия
    │   └── production-v1-architecture.html
    ├── audits/
    │   ├── testing-audit-2026-08-05.md
    │   ├── Аудит решений бота Володи 2026-08-13.md
    │   └── guardrails-pii-provider-side-task.md
    ├── qa/manual/
    │   ├── План ручного тестирования.md
    │   ├── Ручное тестирование человеком.md
    │   └── Ручное тестирование человеком 2.md
    └── superpowers/
        ├── plans/
        └── specs/
```

## Правила

- Корневой HTML остаётся byte-for-byte зеркалом канонического файла из `docs/architecture/`.
- Живые pytest-контракты и текущий архитектурный план переходят на новые пути.
- Старые планы и changelog не переписываются: они фиксируют историческое состояние проекта на момент прошлых работ.
- Внешние системы и секреты не затрагиваются.

## Проверка

Один Docker-прогон проверяет три визуальные схемы, синхронизацию корневого HTML и документированный Compose-контракт. После переноса выполняется `git diff --check` и проверка отсутствия временных Compose-контейнеров.

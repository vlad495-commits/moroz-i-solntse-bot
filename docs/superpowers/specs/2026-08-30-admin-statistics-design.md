# Вкладка «Статистика» для владельца

## Цель и границы

Владелец получает owner-only вкладку `/stats` с достоверной сводкой за выбранный
период. Это доработка только этой вкладки: без новых внешних интеграций, без
изменений Telegram-пайплайна, staging или production.

Страница по умолчанию показывает текущий календарный месяц. Даты `с` и `по`
задаются в московском времени и включают обе границы дня. При неверном диапазоне
страница возвращает понятную ошибку, а не частичную статистику.

## Источники и метрики

Все фактические показатели строятся только по уже сохранённым строкам с
`created_at` в выбранном диапазоне:

| Показатель | Источник и правило |
| --- | --- |
| Пользователи | Уникальные `messages.user_id` для пользовательских сообщений. |
| Сообщения | Все строки `messages`. |
| Автоматические ответы | Успешно доставленные `outbound_messages` с ключом `reply:`. Ответы сотрудника (`admin_handoff_reply:`) и недоставленные сообщения не входят. |
| LLM-вызовы и токены | Суммы `token_usage`; входные, выходные и cache tokens показываются отдельно. |
| Стоимость и экономия на кэше | Аггрегация по фактически записанной `token_usage.model`; берутся только модели с явным тарифом в каталоге. |
| Эскалации | Количество `escalations`. |
| Security-инциденты | `security_incidents`, только если таблица действительно существует. |

Если таблицы нет, в выбранном периоде нет надёжной части данных или модель не
имеет явного тарифа, соответствующая карточка показывает «Нет данных» и краткую
причину. Частичная стоимость не выдаётся за полную: при хотя бы одной строке
`token_usage` без известного тарифа стоимость и cache savings всего периода не
показываются. Нынешняя схема не создаёт `security_incidents`, поэтому на первом
релизе карточка объяснит необходимость начать сохранять инциденты в эту таблицу.

## Расчётная оценка оператора

«Автоматизированные диалоги (расчётная оценка)» — уникальные `chat_id`, для
которых за период есть успешный бот-ответ `reply:`, но нет эскалации для того же
`customer_id` и нет доставленного ответа сотрудника `admin_handoff_reply:`.
Это консервативный operational proxy, не доказательство полного решения
обращения; страница прямо сообщает это ограничение.

Владелец сохраняет два положительных параметра в рублях:

* минуты оператора на один диалог;
* ставку оператора в ₽/час.

До первого сохранения параметров расчётные часы и деньги показывают «Нет
данных: заполните настройки». Формулы всегда видимы рядом с результатом:

```
сэкономленные часы = автоматизированные диалоги × минуты оператора / 60
экономия = сэкономленные часы × ставка оператора
```

Обе итоговые карточки помечены «Расчётная оценка». Настройки хранятся в новой
однострочной таблице `admin_statistics_settings` и доступны на изменение только
owner. POST проверяет CSRF, валидирует положительные значения и пишет audit
event без лишних данных.

## Устройство

Новый модуль выборки в admin слое выдаёт typed/явный snapshot для периода;
маршрут `/stats` остаётся owner-only. Шаблон остаётся в `stats.html`, чтобы
область изменений навигации ограничилась существующей ссылкой «Статистика».
Новая additive Alembic migration создаёт settings-таблицу и нужные индексы по
времени для периодных запросов только там, где они отсутствуют.

Текущая функция `pricing.calculate_cost` с fallback-тарифом не используется для
новой вкладки: статистика применяет только известный тариф модели. Остальные
экраны и их текущие агрегаты не меняются.

## Ошибки, доступ и проверка

Страница, GET-период и сохранение настроек требуют роль `owner`; не-owner не
должен читать данные или запускать запросы к БД. Пустой период корректно
показывает нули только для достоверно измеряемых count-метрик; для отсутствующих
источников и тарифов — «Нет данных» с причиной.

Тесты сначала фиксируют правила периода, исключение эскалаций/сотрудника,
отсутствующие incident/pricing data, расчёт формул, CSRF/RBAC и шаблон. Затем
выполняются только через Docker: targeted unit/integration/admin tests,
migration cycle и релевантный admin regression. Внешние provider-вызовы,
staging, production и push исключены.

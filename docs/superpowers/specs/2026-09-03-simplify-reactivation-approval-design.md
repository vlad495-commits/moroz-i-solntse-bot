# Упрощённое подтверждение запуска Reactivation

**Статус:** согласовано владельцем 2026-09-03. Эта спецификация заменяет требование обязательного `legal reference` для запуска Reactivation V2.

## Решение

Путь запуска сокращается до трёх понятных этапов:

1. аудитория рассчитана;
2. тестовое сообщение доставлено владельцу;
3. владелец видит количество подходящих клиентов и явно запускает рассылку.

Отдельные поле документа, юридический статус, чекбокс и ввод слова `АКТИВИРОВАТЬ` в интерфейсе не нужны. Кнопка запуска остаётся owner-only, защищённой CSRF и дополнительным диалогом подтверждения.

## Текст интерфейса

Карточка перед запуском:

> **Готово к запуску**
>
> Сейчас подходят **N клиентов**.
>
> Сообщение будет отправлено только тем, кто дал согласие на рассылку.

Основная кнопка: **Запустить**.

Диалог после нажатия:

> **Запустить рассылку?**
>
> Сообщение получат только клиенты, которые согласились на рассылку.

Кнопки диалога: **Отмена** и **Запустить**.

При `N = 0` запуск остаётся заблокированным с коротким объяснением, что подходящих клиентов пока нет.

## Гарантии backend

Упрощение интерфейса не ослабляет правила допуска. Для запуска по-прежнему обязательны свежий preview, успешный test-send, актуальные данные и отсутствие identity conflicts. Перед каждой реальной отправкой backend повторно проверяет доказанное marketing consent, suppression, удаление данных, human mode, эскалацию, будущую запись, свежесть YCLIENTS и остальные существующие eligibility/pre-send fences.

Сам checkbox не добавляется: он дублировал бы то, что система обязана гарантировать автоматически. Владелец подтверждает именно запуск, видя актуальное количество получателей.

## Изменения состояния

Первичная кнопка **Запустить** атомарно делает проверенную версию активной и переводит программу в `active`. Возобновление после паузы использует такое же короткое подтверждение, повторно проверяя актуальные launch gates.

Audit фиксирует владельца, время, версию, действие запуска и количество подходящих клиентов из свежего preview.

## Совместимость

Колонки `legal_status`, `legal_reference`, `legal_approved_at` и `legal_approved_by` пока сохраняются без миграции для безопасного отката, но текущий UI, activation gate, scheduler и delivery fence от них не зависят. Старый owner-only endpoint подтверждения основания остаётся недоступным из UI и считается deprecated; удалить его и колонки можно отдельной cleanup-миграцией после стабильной работы новой схемы.

## Не входит в изменение

- правила получения, отзыва и доказательства рекламного согласия;
- eligibility, suppression и pre-send проверки;
- тексты самой реактивационной рассылки;
- production-запуск или отправка реальным клиентам;
- юридическая оценка конкретной рекламной кампании.

## Проверка

TDD должен доказать, что запуск проходит без заполненных `legal_*`, блокируется без свежего preview или test-send, не допускает `N = 0`, сохраняет owner/audit evidence и не ослабляет consent/pre-send fence. Browser QA проверяет точный русский текст, отсутствие старого поля и корректное подтверждение на desktop и mobile.

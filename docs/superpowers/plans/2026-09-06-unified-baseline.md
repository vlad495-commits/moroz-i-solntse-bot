## Global Constraints

- Не терять пользовательские изменения, не применять reset --hard, force push и массовое удаление worktree.
- main изменять только после проверки интеграционного кандидата. Публикация GitHub и staging явно разрешена владельцем в текущем запросе.
- Не запускать живые Telegram/YCLIENTS-сценарии и платные evals; техническая проверка сборки/схемы/health обязательна.
- Секреты staging остаются только на сервере; не заменять server-only .env локальным.
- Сохранить историю обеих завершённых веток и явно описать заменённые более поздним решением механизмы.
- Не включать автоматически сторонние незавершённые инициативы, в частности ЮKassa.

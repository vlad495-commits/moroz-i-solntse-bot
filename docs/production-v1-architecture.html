Полотно 1 · главный runtime

Путь сообщения клиента

Telegram update надёжно фиксируется, проходит privacy gate, очередь, scripts-first маршрутизацию и защищённый LLM-контур. Ответ сохраняется до внешней доставки.

Полотно 2 · защищённая мутация

Запись через YCLIENTS

Запись не делается свободным текстом LLM. Сценарий собирает данные, показывает подтверждение и только затем выполняет одну защищённую внешнюю мутацию.

01 · Domain flow

Booking state machine

Ведёт create, reschedule и cancel по явным фазам.

needs input · confirm · executing · completed/escalated
PostgreSQL booking scenarios и current snapshot
02 · Владение

Owner + booking key

Связывает локального клиента и запись trusted UUID-ключом.

advisory lock · immutable ownership · fail closed
03 · Read API

YCLIENTS: услуги и слоты

Читает актуальные услуги, сотрудников, слоты и запись.

YCLIENTS остаётся источником внешней правды
YCLIENTS API test/production филиал и record field
04 · Human confirmation

Явное подтверждение

Показывает услугу, сотрудника, дату и время до изменения.

без подтверждения provider mutation не выполняется
05 · Protected mutation

Create / reschedule / cancel

Выполняет одну внешнюю операцию без blind retry.

rate limit · exact key · no mutation replay
06 · Проверка результата

Reconciliation

При неизвестном исходе перечитывает provider state по exact key.

не создаёт дубль · unresolved outcome блокирует siblings
07 · После записи

Notification planner

Создаёт durable jobs подтверждения, напоминаний и lifecycle.

одна транзакция с локальным booking checkpoint
RabbitMQ будущая доставка due jobs

При сбое: известная ошибка безопасно завершает сценарий, а неизвестный исход внешней мутации переводит запись на reconciliation/ручную проверку. Автоматического повторного POST/PUT/DELETE нет.

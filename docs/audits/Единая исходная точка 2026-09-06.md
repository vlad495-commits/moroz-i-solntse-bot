## Разрешение расхождения архитектур

Владелец явно подтвердил: последняя итерация — **свободный диалог**, а не меню 2×3 старого staging. Поэтому объединение истории не означает восстановление всех старых runtime-файлов.

- Меню, каталог консультаций, подбор по фиксированным целям и wizard history заменены новым согласованным контрактом.
- Ограничения времени, STOP, walk-in, ownership и безопасное повторное подтверждение уже покрыты новым координатором.
- Сохраняются совместимые UX-возможности: обновление одной inline-карточки внутри сценария, нормализация отображаемых названий, читаемые ссылки без preview.
- Contact keyboard, обычный текст, смешанная консультация и финальный результат операции не должны затираться редактированием карточки.
- Старые callback codes не копируются. Содержательная база — ручной system.md, без второго прайса и старых hardcoded описаний.

## Правила Git после синхронизации

- Единственная точка начала новой работы — актуальный `main`, синхронизированный с `origin/main`.
- Новая работа — отдельная `codex/*` ветка от актуального main; не продолжать старые альтернативные ветки как будто это текущая версия.
- Staging обновляется только зафиксированным проверенным кандидатом с immutable `rc-<full SHA>`; Git checkout и image IDs сверяются отдельно.
- Не переписывать историю опубликованных коммитов и не применять force push.
- Старые ветки без уникальной работы можно удалить через `git branch -d` после проверки ancestry и отсутствия привязанного worktree. Работающие worktree и ветки с уникальными коммитами не удаляются автоматически.
